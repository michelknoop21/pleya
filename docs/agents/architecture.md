# Client architecture and playback

Read only when the task touches this domain. Inline code paths are relative to the repository root.

- **Dual backend.** Plex and Jellyfin are parallel implementations, not a shared interface: `services/plex_client*` + `plex_mappers` vs `services/jellyfin_client*` + `jellyfin_mappers`. Each has its own auth service and API cache; mappers convert backend responses into the shared `lib/models/` types the UI consumes. When adding a feature, expect to touch both sides.
- **Profiles → connections → servers.** `lib/profiles/` models Plex Home profiles (with PIN entry, active-profile binding). A profile owns one or more server connections registered in `lib/connection/` (`connection_registry`, `connection_bootstrap`, auth) and `providers/multi_server_provider.dart` / `services/server_registry.dart` + `multi_server_manager.dart`. `data_aggregation_service` fans queries across servers. `main.dart` wires this bootstrap sequence at startup.
- **State = `provider` (ChangeNotifier).** No Riverpod/Bloc. App-wide notifiers live in `lib/providers/`; they're registered as a MultiProvider in `main.dart`. Prefer extending existing providers over introducing a new state solution.
- **Playback = mpv.** `lib/mpv/` wraps libmpv/MPVKit for the player. `metadata_edit`, `watch_together` (peer-synced playback via `base_peer_service`), downloads, and trackers hang off the playback flow.
- **Local DB = drift.** `lib/database/` (`app_database`, `tables`, `download_operations`) is the SQLite store for downloads/offline state; `app_database.g.dart` is generated by build_runner. Offline mode + watch-state sync-back is coordinated by `offline_watch_sync_service` and the offline providers.
- **Adaptive UI + TV focus.** `lib/screens/` and `lib/widgets/` render across desktop/mobile/TV form factors; `lib/focus/` handles D-pad/remote focus traversal for TV. Navigation lives in `lib/navigation/`.

## Server authority (owner rule)

Only the owner of a server may change canonical metadata (metadata, artwork, match, collections, media deletes, library maintenance, subtitle downloads, cancelling server tasks). The single predicate is `MultiServerManager.canManageServerMetadata`; the UI hides these actions when it returns false, and every such client method calls `assertCanManageServerMetadata()` first, so an unwired or non-owner client refuses with a 403 before any request. Watch state, ratings, watchlist, playlists and per-user stream selection stay open to everyone.

- Plex: `owned`, unless the active profile is a non-admin Home member or holds the account through a join row (join rows are always borrowed).
- Jellyfin: `IsAdministrator` counts as owner (owner decision, 25 Sep 2026: Jellyfin has no owner role). A join row with `borrowed == true` never gets it.
- Pleya Server: always false until PS-9 delivers roles; then only `role == owner`.
- Tautulli and "Watched by" read admin data through `isOwnerOrAdmin`, a separate probe that ignores borrow restrictions (a borrowed token can already read `/status/sessions` from Plex). Administering Tautulli (pair, policy, unlink, the settings tile and search entry) is device-wide and needs `canManagePlexServer`: owner rights on a Plex server, so neither a borrowed connection nor a Jellyfin-only administrator gets it.

Pre-v20 Jellyfin borrow rows get `borrowed` from a one-time backfill (`lib/profiles/borrowed_connection_backfill.dart`, flag `profile_connections_borrowed_backfill_v20_done`), run by `runStartupMaintenance` (`lib/profiles/startup_maintenance.dart`) before `binder.start()`. The binder binds every Jellyfin row with the connection's current `accessToken`, so in a connection with two or more rows a row whose effective token differs from it is stale and becomes borrowed; this also catches a lender who signed in again after lending. Of the rows that carry `accessToken`, the unique earliest `tokenAcquiredAt` stays owned, and a tie or unknown time marks them all borrowed. Accepted false positive (closed side): an owner who signed in separately on two profiles loses the rights on the older profile until signing in again there, which clears `borrowed`. Residual: a borrowed row whose source profile was deleted is the only row of its connection and cannot be told apart from an own login.

Known limits of the owner rule (none grants rights except the plaintext-era case, which no install should reach):

- The backfill flag lives in shared preferences, the rows in Drift. A prefs reset (which also loses the vault key, so tokens become unreadable and fall back to `accessToken`) reruns the backfill on a post-v20 database; two own logins on two profiles then look like copies and one profile loses its rights until it signs in again.
- Rows from the plaintext-token era got `tokenAcquiredAt = now` when `_rowToModel` re-recorded them, milliseconds apart and in arbitrary order, so the earliest-time rule could pick the borrower there. Pleya started on a base that already had CredentialVault, so no install should carry such rows.
- Plex join rows are always borrowed, so an owner working from a local profile never has Plex owner rights on that profile; signing in again does not change it (`add_plex_account_screen` binds with `bindToProfile: null`). The Home admin profile keeps them.
- Two Plex accounts on one profile that both see the same server: the account that binds last sets `_clientIdByServer` and `_plexServers` for that server. Identity and `owned` always come from the same account, so this can drop rights on that server (non-deterministic, network timing) but never grants them.
- The Verify scenario `tvos.authority.non-owner` runs on the Pleya Server fixture, where the predicate is always false. It proves the UI hides owner actions when `canManageServerMetadata` is false, not that the predicate is false for a borrowed row or a Plex Home member; those paths are covered by unit and widget tests only.

## Temporary overrides

- **Tijdelijke overrides (rate-boost, background-pause, e.d.):** nooit los een "waarde-vóór"-veld bijhouden — een re-entrante start-handler (dubbele gesture/lifecycle-event) overschrijft de captured waarde met de al-geboden waarde en dan blijft de override permanent hangen. Gebruik `lib/utils/temporary_override.dart` (`TemporaryOverride<T>`: engage capture't éénmalig, release herstelt éénmalig), of minimaal een `if (alActief) return;`-guard op de start-handler én een reset op elk cancel/lifecycle-pad.
